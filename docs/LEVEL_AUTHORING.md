# 关卡制作规范

## 从描述到关卡

1. 明确来源：原文规定、用户补充或后续扩展，不把自拟内容写成原文要求。
2. 填写关卡设计表，确保线索、正确操作、错误解释和结算知识相互对应。
3. 写入 `levels.json`，复用已存在的枚举 ID 或同步扩充 `types.ts`。
4. 用已认可的人物风格生成素材，检查人物一致性、服装、朝向、基线和透明边缘。
5. 配置素材与音效，复用运行逻辑；需要新交互时先明确交互规则。
6. 执行测试与手机/桌面截图检查，修好后写入实际项目。

## 当前配置约定

- `designSource` 标记来源，`knowledge` 记录主知识点；这两个字段用于文档对照。
- `zones` 与 `targets` 一一对应，每目标最多计分一次，分数总和为 100。
- `tools` 至少覆盖所有目标，额外项必须有可解释的错配反馈。
- `observeFirst` 开启时，目标必须被查看才能计分。
- `progressArt` 可选，表示首项完成的通用插画；无该图时沿用已有轻动画。
- `successSound` 配在每个目标上；音频使用短本地 WAV，不依赖外部服务。
- `beforeArt`、`afterArt`、工具图片和可选中间图必须真实存在。

## 合格标准

不能只更换名字和立绘就声称是新玩法。每个新关至少新增一个观察结论、判断区别或操作信息。

医学相关设定须清楚区分游戏简化与真实个体情况；图片保持卡通示意。发布前若使用新的医学主张，先核对对应资料，再写科普文案。

两种操作顺序、错误与重复、取消触摸、提示遮挡、重玩、切关延迟、小屏溢出与音效开关都纳入验证。Creator/微信真机验证另记，不用浏览器测试代替。

## 用户补充的内容方向（2026-10-05）

新增内容规范见 `CONTENT_RULES.md`，职业选题见 `LEVEL_ROADMAP.md`。生成关卡时同时遵循这两份文档。

每关设计表追加：工种与具体任务、持续/重复/负荷线索、肌肉名称与白话位置/作用、可能机制及对应资料、改善路径、操作反馈、通关摘要、展开科普卡、来源与适用边界。

来源标记中，用户明确补充的内容可沿用运行配置的 `extension`；文档须注明用户方向。当前 JSON 已有 `education` 字段（summary、cause、muscles、actions、boundary、sources），浏览器与 Cocos 学习卡读取同一份内容。每条 muscle 必须包含 name、location、function；每条 source 包含 title 和 HTTPS url。

## 健身主线修订（2026-10-06）

后三关使用 `fitness: true`；目标增加 `demoArt`，每次正确配对显示该动作，不显示工位改善或瞬间治愈。`education.actions` 增加 `art`、`steps`、`principle`、`caution`，和目标的示意图一一对应。`workTip` 仅作职业补充提示，不计分。规范优先遵循 `CONTENT_RULES.md` v1.1。

两个“正确方法”可能有生理作用重叠，错配解释必须说明当前学习的是哪种方法/部位，不能为了唯一答案谎称其他活动绝无帮助。图像只展示动作，不证明疗效；检查支撑点、器械接触部位、关节位置与文字是否一致。

## 肌肉位置图（2026-10-06）

每个肌肉介绍条目应配置 `anatomy`，包含本地图片、观察方向、图例、深浅层说明与解剖参考来源。分侧或移开覆盖层必须写明；颜色只用于识别结构，不表示诊断。图片高亮区域必须对应本条目，不能为了好看把邻近肌肉也上色。页面需说明原创建图为简化示意，正式发布前专业审阅另行验收。
